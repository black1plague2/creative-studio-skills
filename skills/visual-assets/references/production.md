# Visual assets: production rules

These rules apply to the selected task and supplied brief. Use judgment for reversible choices; preserve explicit user requirements.

## 1. Classify the asset: photography, narrative illustration, product mockup, texture, character scene, or exact graphic

Classify the asset: photography, narrative illustration, product mockup, texture, character scene, or exact graphic. Match the tool to the asset; a decorative bitmap is unsuitable for an exact numeric chart or logo that requires vector editability.

## 2. Describe subject, scene, composition, materials/medium, palette, lighting/mood, text if any, and invariants

Describe subject, scene, composition, materials/medium, palette, lighting/mood, text if any, and invariants. Add concrete detail only when it supports the intended message; do not turn a small brief into an unrelated narrative.

## 3. Label every input image by role: identity reference, style reference, exact supplied artwork, composition guidance, or edit target

Label every input image by role: identity reference, style reference, exact supplied artwork, composition guidance, or edit target. A style reference does not grant permission to replace a supplied logo or copy another artist's image.

## 4. For a set, establish a reusable visual grammar and character/object sheet

For a set, establish a reusable visual grammar and character/object sheet. Record clothing, silhouette, proportion, accessory, palette and camera/composition rules. Check continuity in actual outputs.

## 5. Use exact text sparingly in generated artwork and verify it visually

Use exact text sparingly in generated artwork and verify it visually. For long copy or strict brand marks, prefer a separate controlled text/layout layer when the user permits it. The GPT slide workflow has its own full-poster contract.

## 6. For edits, inspect the original and enumerate changes and invariants

For edits, inspect the original and enumerate changes and invariants. Keep a new version rather than overwriting the only original. Use the available editing capability rather than claiming a mask or tool parameter that the host does not support.

## 7. For a transparent cutout, request actual transparency and verify the alpha channel and edge halos

For a transparent cutout, request actual transparency and verify the alpha channel and edge halos. A checkerboard painted into an opaque file is not transparency.

## 8. Inspect anatomy, object topology, unwanted text, brand collisions, cropping, edge artifacts, and consistency with the real-world subject

Inspect anatomy, object topology, unwanted text, brand collisions, cropping, edge artifacts, and consistency with the real-world subject. Reject a beautiful image that misrepresents required hardware or an actual product.

## 9. Save selected outputs in the project with descriptive filenames and their final prompts/reference roles

Save selected outputs in the project with descriptive filenames and their final prompts/reference roles. Generated assets referenced by a project must not live only in an inaccessible temporary tool location.

## 10. Deliver the selected files, intended use/crop notes, and material limitations

Deliver the selected files, intended use/crop notes, and material limitations. Do not call an image a real product screenshot or a measured technical result unless the source supports it.
