# Website front ends: production rules

These rules apply to the selected task and supplied brief. Use judgment for reversible choices; preserve explicit user requirements.

## 1. Inspect the existing code and product truth before design

Inspect the existing code and product truth before design. Reuse the established stack, tokens, components and behavior where appropriate. A styling request is not authorization to migrate frameworks or invent a backend.

## 2. Research relevant examples, identify what makes them work, and choose a distinctive direction grounded in subject matter

Research relevant examples, identify what makes them work, and choose a distinctive direction grounded in subject matter. Record imagery roles, type hierarchy, composition, density and copy voice.

## 3. Write real section content around the visitor's decision

Write real section content around the visitor's decision. Do not default to hero/features/pricing/FAQ simply because it is familiar. Include only sections supported by the product and brief.

## 4. Use truthful screenshots, demos, customer claims and offer terms

Use truthful screenshots, demos, customer claims and offer terms. A concept mockup must be labeled as such; placeholder testimonials and invented usage statistics must not ship.

## 5. Build hierarchy with layout, typography, spacing and purposeful media

Build hierarchy with layout, typography, spacing and purposeful media. Match asset crop and quality to the design. Do not substitute a random stock illustration for a missing product demonstration.

## 6. Implement semantic actions/navigation, visible keyboard focus, appropriate input labels, error feedback and useful loading/empty states

Implement semantic actions/navigation, visible keyboard focus, appropriate input labels, error feedback and useful loading/empty states. Keep an accessible control's semantics even when styling it boldly.

## 7. Design narrow and wide layouts structurally

Design narrow and wide layouts structurally. Check long text, menu expansion, actual forms, sticky elements, image loading and text zoom. A resized desktop screenshot does not establish responsive behavior.

## 8. Use motion for a clear reveal, feedback or explanation

Use motion for a clear reveal, feedback or explanation. Honor reduced motion and provide pause controls where required. Avoid scroll-jacking or animation that blocks the primary action.

## 9. Run the relevant build/checks and inspect actual browser output

Run the relevant build/checks and inspect actual browser output. Exercise the main visitor journey and identify untested integrations. Automated accessibility checks complement manual keyboard/semantic review.

## 10. Deliver project files and run instructions, with any required deployment step separate

Deliver project files and run instructions, with any required deployment step separate. Publish only when the user authorizes it; do not call a static frontend a functioning payment/signup integration.
