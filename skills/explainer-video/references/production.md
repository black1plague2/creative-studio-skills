# Explainer video: production rules

These rules apply to the selected task and supplied brief. Use judgment for reversible choices; preserve explicit user requirements.

## 1. Extract claims into a fact ledger, then write for speech

Extract claims into a fact ledger, then write for speech. Select a clear story and a concrete running example. A video script is not a PDF paragraph read faster.

## 2. Establish runtime range, language, canvas, frame rate and delivery target

Establish runtime range, language, canvas, frame rate and delivery target. Use roughly 45–90 seconds as a possible short-explainer brief, not a universal cap. Measure the actual voice before locking scene durations.

## 3. Create a storyboard row per beat: spoken anchor, visible action, subject/asset, on-screen text, continuity constraints, timing basis, caption and transition

Create a storyboard row per beat: spoken anchor, visible action, subject/asset, on-screen text, continuity constraints, timing basis, caption and transition. Each visual explains or demonstrates something.

## 4. Maintain a visual grammar: palette, typography, stroke/texture, character/object identity, device colors, screenshot frames and progress cues

Maintain a visual grammar: palette, typography, stroke/texture, character/object identity, device colors, screenshot frames and progress cues. A new topic can establish a new direction; it need not look like the repo example.

## 5. Use provided product screenshots/footage where they show real behavior

Use provided product screenshots/footage where they show real behavior. Label conceptual mockups. Isolate mechanisms with purposeful illustration rather than placing an unreadable full screenshot on every scene.

## 6. Animate state/action: an item changing hands, progress completing, files moving, a comparison updating, or a user decision revealing its consequence

Animate state/action: an item changing hands, progress completing, files moving, a comparison updating, or a user decision revealing its consequence. Avoid reducing the deliverable to panning over dense slide images.

## 7. Route narration through the natural-voiceover skill and its listening gate

Route narration through the natural-voiceover skill and its listening gate. Keep one narrator/voice model where continuity matters; align picture and captions to measured speech and verify joins.

## 8. Build a representative short pilot before an expensive full render when direction is unclear

Build a representative short pilot before an expensive full render when direction is unclear. Check pace, text size, motion, voice and asset continuity together. Revise the shared system, not each scene independently.

## 9. Use the suitable available engine: timeline editor, programmatic motion, 2D/3D animation or compositing tools

Use the suitable available engine: timeline editor, programmatic motion, 2D/3D animation or compositing tools. Verify current API behavior and dependencies. Do not attribute the supplied reference video to a tool its metadata does not identify.

## 10. Cut redundant beats before accelerating speech

Cut redundant beats before accelerating speech. Preserve pauses and enough reading time for visible labels. Transitions should maintain continuity; use audio/picture offset cuts when they serve the explanation.

## 11. Review complete final playback and audio; also inspect frames at cuts, caption changes, first/last moments and dense labels

Review complete final playback and audio; also inspect frames at cuts, caption changes, first/last moments and dense labels. Check duration, dimensions, frame rate, codec/audio streams and target-specific loudness. A clean frame sample does not prove every transition is clean.

## 12. Deliver the requested final video, captions/transcript and editable project/source/asset records

Deliver the requested final video, captions/transcript and editable project/source/asset records. An animatic or silent motion demo must be labeled as such; it is not a finished narrated video.
