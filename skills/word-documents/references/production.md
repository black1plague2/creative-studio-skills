# Word documents: production rules

These rules apply to the selected task and supplied brief. Use judgment for reversible choices; preserve explicit user requirements.

## 1. Inspect paragraph, run, style, list, table, section, header/footer and field structure before editing

Inspect paragraph, run, style, list, table, section, header/footer and field structure before editing. A form made from tabs/underscores requires different handling from a real content control or table.

## 2. Keep the original and make a separate output unless the user asked to edit in place

Keep the original and make a separate output unless the user asked to edit in place. Convert legacy inputs through a suitable Office-compatible route when necessary and inspect the conversion.

## 3. Use semantic heading/list/table styles and explicit page/section settings

Use semantic heading/list/table styles and explicit page/section settings. Do not simulate columns, dot leaders or alignment with long runs of spaces; avoid replacing formatted runs with an unstyled entire paragraph.

## 4. Preserve exact names, dates, numbers, units, source figures and citations

Preserve exact names, dates, numbers, units, source figures and citations. Fill only supplied field values. Missing user data is a question, not an invitation to invent it.

## 5. For a form, match underline/tab and field conventions while testing rendered width

For a form, match underline/tab and field conventions while testing rendered width. Equal character counts do not imply equal visual width. Confirm that added values do not unexpectedly move nearby content.

## 6. Design tables for width, row splitting, header repetition, labels and long entries

Design tables for width, row splitting, header repetition, labels and long entries. Keep pictures sharp and proportionate. Do not rely on a file opening as proof that its tables fit.

## 7. Implement requested tracked changes/comments with an appropriate supported method

Implement requested tracked changes/comments with an appropriate supported method. Do not claim genuine Word revision semantics if the result only uses colored text or a comparison summary.

## 8. Render with Word or a documented compatible engine

Render with Word or a documented compatible engine. Compare affected pages before/after for layout-sensitive edits. Review full output after changes that influence page flow.

## 9. Check TOC/headings, captions/cross-references, numbering, headers/footers, sections, breaks, missing glyphs, footnotes and placeholder text

Check TOC/headings, captions/cross-references, numbering, headers/footers, sections, breaks, missing glyphs, footnotes and placeholder text. Font substitution can change wrapping; disclose the renderer used.

## 10. Deliver DOCX and any requested PDF companion

Deliver DOCX and any requested PDF companion. Retain authoring sources or the edit ledger when useful. Explain real renderer/field limitations without presenting visual checks as accessibility certification.
