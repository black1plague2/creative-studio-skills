# Adaptable poster-deck structures

Choose a structure for the audience's job, then honor the actual requested count and source material. These are original reusable structures informed by the research, not copied upstream decks or fixed slide-count requirements. Every slide remains a complete GPT-generated 16:9 poster by default.

## Product / startup pitch

Typical narrative: concept → concrete problem → what changes → product mechanism → user journey → evidence or validation plan → business/operating model if supplied → next step.

Use lived scenes and actual actors/objects. Keep proposed versus implemented features distinct. If traction or market data is absent, omit it or use an explicitly sourced validation plan rather than inventing attractive numbers. A visual prototype is not a real product screenshot.

Slide record: role, audience question, exact copy, source status/location, central scene/metaphor, technical constraints, density, reference roles, prompt, inspected image, export order.

## Technical / system explanation

Typical narrative: purpose → actors/components → inputs and constraints → mechanism/architecture → decisions and failure/recovery → user/operating flow → boundaries → evidence/next step.

Architecture is an illustrated plate with meaningful objects and faithful connectors. Preserve component names, branch directions, labels, ownership, data boundaries and qualifiers. Show “proposed” or “unverified” wherever the source requires it. Do not hide a critical dependency in tiny decorative text.

Review the densest plate early. Check topology and copy separately from visual style. Native reconstruction or separated text remains an explicit alternate exception, not a default way to avoid GPT generation.

## Educational / instructional

Typical narrative: motivating concrete example → concept → one mechanism at a time → guided example → comparison or misconception → practice/check → recap or next action.

Let the visual do explanatory work: show a process changing, cause/consequence, or an object used differently. Do not turn every idea into the same labeled-box diagram. Match jargon and reading density to the learners. A practice question needs a source-grounded answer, not just a decorative “quiz” label.

For a lecture, slides support speech; for a handout, each image may need a more self-contained explanation. A fixed “one slide per minute” ratio is a planning convention, not a universal rule.

## Research / evidence briefing

Typical narrative: question/context → source and method → results → interpretation and uncertainty → comparison → implications within the evidence → limitations → decision or further work.

Exact figures, equations and quantitative relationships need special care. Preserve original measured evidence and units; do not assume a generated chart is accurate. If the user's full-GPT-poster and exact-data requirements cannot both be verified, identify the conflict and ask for an explicit evidence exception or revised content. Do not falsely label a redrawn illustration a measured result.

Use topic-specific imagery and a readable evidence hierarchy. An impressive title cannot crowd the supporting data into unreadable sidebars. Provide a transcript/figure descriptions where needed.

## Choosing and adapting

Start from a real brief. Combine or trim roles only when it preserves meaning. A three-slide request can be concept/problem/flow; it cannot secretly become an eight-slide pitch. Use the local production template for exact copy and prompts, and the live domain pack when available for audience/evidence constraints. The skill works standalone with a user-provided domain brief.
