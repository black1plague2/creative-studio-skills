# GPT poster slides: production rules

These rules apply to the selected task and supplied brief. Use judgment for reversible choices; preserve explicit user requirements.

## 1. Use GPT image generation for the complete slide: imagery, hierarchy, labels, and typography are part of the generated poster

Use GPT image generation for the complete slide: imagery, hierarchy, labels, and typography are part of the generated poster. This is a provider-specific instruction, not permission to pretend an unavailable image tool exists.

## 2. Read source files first

Read source files first. Extract exact names, numbers, units, product status, caveats, and real figures. Treat architecture and user-flow content as potential illustrated technical plates, not as a reason to create a plain text diagram.

## 3. Plan every slide with an explicit role, main message, required content, visual mechanism, and density

Plan every slide with an explicit role, main message, required content, visual mechanism, and density. A fixed count includes the cover and closing page unless the user says otherwise. Do not invent a thank-you slide just to fill a count.

## 4. Choose a coherent topic-specific visual language

Choose a coherent topic-specific visual language. Record palette, type roles, illustration medium, character/object continuity, motifs, grid/safe margins, and diagram vocabulary. Do not force every project into a fixed green sketchbook preset.

## 5. Test a cover and a representative content-heavy slide when direction is unresolved

Test a cover and a representative content-heavy slide when direction is unresolved. A beautiful cover can hide a poor architecture or workflow layout. Honor an already chosen direction without asking for confirmation again.

## 6. Write a standalone prompt per slide using verified copy, desired visual roles, full-slide composition, exact landscape 16:9 canvas, reference roles, and continuity constraints

Write a standalone prompt per slide using verified copy, desired visual roles, full-slide composition, exact landscape 16:9 canvas, reference roles, and continuity constraints. Save prompts before calling the generator. Use supported controls; do not invent a size argument.

## 7. Pass the selected reference or previous approved image when the host supports it

Pass the selected reference or previous approved image when the host supports it. Specify what it controls: visual identity, character continuity, palette, or object shape. Do not import the reference deck's topic, labels, or personal information.

## 8. Generate separate slide images

Generate separate slide images. A montage of several slides is not the requested slide set. Dense text must be shortened faithfully or split across slides before generation; text that cannot be verified fails acceptance.

## 9. Inspect the actual image, not only the prompt

Inspect the actual image, not only the prompt. Read every letter and numeric label, verify arrows/relationships, check crops and proportions, and compare the full deck. Regenerate or use the supported GPT editing route for defects. Do not disguise misspelled text with unreviewed patches.

## 10. Use the local helper manifest for ordered packaging

Use the local helper manifest for ordered packaging. Keep the full image visible, with exact 16:9 PDF/PPTX pages; refuse stretching and meaningful cropping. A native size rounded within one pixel is documented by the validator. If an exact PNG canvas is required, request a supported exact-size generation/export route.

## 11. A rasterized plot generated by an image model is not a faithful quantitative figure by default

A rasterized plot generated by an image model is not a faithful quantitative figure by default. If exact measured data must be preserved, attach the original as supporting evidence and require verified depiction, or ask for an explicit deterministic-chart exception. Keep the claim ledger unchanged.

## 12. Deliver final slide images and requested PDF/PPTX, plus exact-copy and prompt records

Deliver final slide images and requested PDF/PPTX, plus exact-copy and prompt records. Do not promise editable text in an image-based PPTX. Provide a transcript when accessible/searchable text is needed. Keep an editable-object version optional and explicit.
