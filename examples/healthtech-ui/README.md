# Morrow Care — healthtech UI example

Open [the runnable patient portal](index.html) in a modern browser or serve this directory locally. This is the original healthtech sample accepted by the user, built using the repository's universal/app-interface guidance. It expands the runnable examples beyond the campus concept.

The paper-and-sage design prioritizes a next appointment, chronological care journey, visit preparation and administrative documents. It has overview/appointments/documents navigation, provider/day/time booking, field recovery and confirmation, appointment filters and local cancellation, document search/preview/download, session notes and reset.

All people, clinicians, dates and records are fictional. State stays in page memory and clears on reload. No real appointment, provider contact, login, payment, database or clinical guidance is connected. Native dialog and modern CSS are required; no install, network calls or external assets are needed.

The accepted design remains unchanged. For a future UI request, first show [three concrete direction examples](../ui-directions/README.md) adapted to that task and let the user choose. The chooser is a comparison example; it does not replace this working flow.

## Actual check scope

The creating agent checked JavaScript syntax. Root inspected the desktop render, triggered missing-day/time recovery, booked a fictional visit, observed confirmation and the updated appointment list. Additional checks and any unrun scenarios are recorded in the repository validation record. The example is an interactive concept, not a deployed medical service or accessibility certification.
