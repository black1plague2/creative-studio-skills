# Editorial document example

This original treatment shows how a PRD becomes a reading-first briefing or an editable Word document. It is a worked production specification, not a claim that a PDF/DOCX was generated here.

Source: [CampusCart fictional PRD](../campuscart/source-prd.md).

## Two-page reading-first PDF plan

| Page | Purpose | Composition and source requirements |
|---|---|---|
| 1 | Explain audience, problem hypothesis and concept | Clear concept-status label; readable body; one useful campus illustration; no adoption metrics |
| 2 | Explain operation and outstanding requirements | Three-stage flow; requirement identifiers; unavailable-item/invalid-date behavior; unresolved risks and next step |

Start with body typography and a page grid. Keep figures/captions together; use semantic headings and exact source copy. Inspect every final page for table width, page breaks, running furniture, clipping and figure legibility. A cover alone does not establish interior quality.

## Editable Word treatment

Use real paragraph/heading/list/table styles. Preserve the concept-status label, exact names and numbered requirements. Keep original figures proportionate. A TOC is unnecessary for a short document. Render the DOCX in a documented compatible engine and inspect the pages; do not call a successful save a layout check.

## Example language

> CampusCart is a fictional campus borrowing concept. A student finds an item, agrees a handoff with its owner, and returns it. The exercise does not implement a backend, payment or identity verification, and supplies no adoption data.

The source hypothesis remains a hypothesis. Good copy and illustration do not convert it into verified demand. Use the editorial-PDF/Word skills to produce real files when a live task requests them.
